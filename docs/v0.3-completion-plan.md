# V0.3 completion plan

Date: 2026-10-14. Source: the 2026-09-23 v0.3 implementation specification.

The release path ends at missed-call recovery, qualification and booking.
Estimates, RAG and AI voice remain later milestones. Existing outbox, messaging,
workflow condition/wait/send, booking APIs and static frontend are retained.

User decisions: OpenAI is the first LLM adapter. Prepare GCP Terraform; applying
it and performing live staging/restore drills require deployment inputs.

## Implementation

1. Extract the booking application and policy into a shared revenue package so
   API users and worker tools enforce identical rules. Add typed qualification,
   grounded prompts, an OpenAI Responses adapter and bounded agent execution.
2. Persist and reconcile asynchronous workflow actions; add agent/booking and
   handoff execution without holding database transactions during model calls.
3. Add controlled missed-call intake, remodeling template installation and
   configured response/follow-up workflows. Preserve opt-out, idempotency and RLS.
4. Add integration provisioning/OAuth, structured logs, tenant operational
   metrics and inspectable runs/handoffs in the operations frontend.
5. Add deterministic critical-path E2E, isolation, failure/retry and receptionist
   evaluations. Run existing security, unit, integration, build and static gates.
6. Prepare GCP infrastructure, deployment/smoke scripts, secret injection and
   backup/restore/rollback runbooks. Document which live checks remain unverified.

Impacted modules: API integrations/intake/templates/operations, worker workflows
and agents, shared contracts/queues/integrations/database, revenue package,
operations frontend, CI and infrastructure.

## Remaining release gates

The product owner selected OpenAI and requested prepared Terraform. Set provider
credentials and explicit tenant model configuration using
`docs/v0.3-local-setup.md`. Supply GCP inputs before applying the module; run the
provider, TLS/origin/session/proxy, queue recovery, restore, rollback and alert
checks in `infra/runbooks/v0.3-readiness.md` against staging. CI was extended with
the release E2E and infrastructure gates; a GitHub run has not been executed here.

The audit found existing frontend tooling vulnerabilities. Published fixes for
simple-git, its argv parser, shell-quote and source-map-js are pinned in overrides.
A one-line Nuxt DevTools patch adapts its import to the fixed simple-git API.
The high-severity gate remains enabled and fails for:

- node-forge 1.4.0: [GHSA-86w9-cpqp-85rv](https://github.com/advisories/GHSA-86w9-cpqp-85rv).
- braces 3.0.3: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).

Both advisories report no patched release as of the check date. They are reached
through existing Nuxt CLI/Nitro tooling; no exemption suppresses the CI gate.
The report also contains one low-severity finding. Resolve these upstream
advisories or review a maintained replacement before declaring CI/release ready.

Knowledge/RAG, full AI voice, estimates and estimate follow-up stay outside this
v0.3 missed-call-to-booking exit path. Backlog completion statements are scoped to
the demonstrated checks; they do not claim that production rollout is complete.
